本文档在需求分析之上补充产品目标、版本切片、界面要求和技术建议。设备状态、领用单状态、提醒对象和权限边界以需求分析文档为准。本文对版本范围做了一处产品调整：归还确认纳入 MVP，否则已领用设备无法回到在库。续借仍放在 V1.1。

## 1. 产品概述和目标用户

### 1.1 产品概述

资产管理系统是面向单一研究机构或事业单位的 Web 应用，用来管理笔记本、台式机、显示器、鼠标、键盘、转接头、投影仪等 IT 办公设备。管理员维护台账并发放设备，职工在线申请领用，系统在到期前和逾期后自动提醒。

产品只服务一个机构，审批为单级。角色只有系统管理员和普通用户。部门、课题组、实验室是归属数据，不单独成为一种角色。

### 1.2 要解决的问题

| 现状 | 产品对应能力 |
| --- | --- |
| 台账散落在表格里，编号和存放地点对不上 | 统一设备台账，资产编号唯一 |
| 领用靠口头，没有审批留痕 | 申请、审批、发放、归还全程留痕 |
| 到期后设备长期滞留在个人手中 | 到期前、到期当天、逾期后自动提醒 |
| 筛选和汇总靠手工 | 组合过滤，首页图表按角色展示 |
| 批量入库和报送没有标准文件 | 模板导入、按筛选结果导出 |
| 职工能看到不该看的价格和他人数据 | 管理员视图与普通用户视图分离 |

### 1.3 产品目标

MVP 上线后，机构可以：

- 把现有表格设备导入系统，并按类型、状态、领用时间、到期时间查到设备。
- 让职工提交领用申请，由管理员审批并发放；归还后设备回到在库。
- 在到期前 7 天、3 天、1 天、到期当天和逾期后，向管理员发汇总站内信，向领用人发站内信和邮件。
- 在首页看到与本人权限一致的数量和图表。
- 用两种角色区分菜单、字段和数据范围。

### 1.4 成功标准

- 管理员能在 10 分钟内完成一批设备导入，并看清失败行原因。
- 职工能在 3 分钟内对一台在库设备提交领用申请。
- 管理员当天能处理完全部待审批、待发放、待归还。
- 到期提醒当天可在消息中心核对，邮件失败时可重试，站内信不丢失。
- 普通用户看不到购置价格、他人领用说明和全机构统计。

### 1.5 目标用户

| 角色 | 是谁 | 使用频率 | 核心任务 | 不做什么 |
| --- | --- | --- | --- | --- |
| 系统管理员 | 信息中心或资产岗，通常 1～5 人 | 每个工作日 | 入库、审批、发放、催还、导入导出、管用户 | 不替职工填写用途 |
| 普通用户 | 科研和行政人员 | 偶尔领用，到期前后会打开 | 找设备、提交申请、看进度、收到提醒、申请归还 | 不改台账、不审批、不导出全量数据 |

一名用户只绑定一个角色。系统始终至少保留一名启用的系统管理员。

### 1.6 典型场景

1. 资产岗把年度采购的笔记本按模板导入，系统标出重复资产编号。
2. 课题组成员筛选“在库 + 笔记本”，填写用途和预计归还日并提交。设备变为审批中。
3. 管理员在待办中通过并做发放确认。设备变为已领用，申请人收到站内信。
4. 到期前 3 天，管理员收到一份即将到期汇总；领用人收到站内信和邮件。
5. 领用人发起归还，管理员验收后确认。设备回到在库，可再次被申请。
6. 管理员打开首页，看在库占比、类型分布和逾期数量，并点进逾期列表。

### 1.7 范围边界

本版包含设备台账、领用闭环、提醒、统计、导入导出、用户角色和双视图。

本版不包含：多机构隔离、多级会签、自定义权限、采购预算、财务入账、二维码与资产标签打印、移动端 App。邮件依赖机构已有的邮件发送服务；未配置时领用和站内信仍可用。

## 2. 详细功能列表

信息架构按角色出菜单。未授权菜单不展示；直接访问地址时返回无权限。

管理员菜单：首页、设备台账、领用办理、消息中心、系统管理。  
普通用户菜单：首页、设备、我的领用、消息中心、个人中心。

### 2.1 登录与个人中心

| 项 | 说明 |
| --- | --- |
| 用户故事 | 作为职工，我用账号密码登录，并维护自己的邮箱，以便收到到期邮件 |
| 功能 | 登录、退出、修改密码、个人资料、首次登录强制改密 |
| 规则 | 仅启用用户可登录。连续失败 5 次锁定 15 分钟。失败提示统一为“账号或密码错误”。普通用户邮箱必填，格式合法才能保存。重置密码后下次登录必须修改密码 |
| 页面 | 登录页、个人中心 |

### 2.2 设备台账

| 项 | 说明 |
| --- | --- |
| 用户故事 | 作为管理员，我登记一台设备，使它可以被查询和领用 |
| 字段 | 资产编号（唯一、必填）、资产名称（必填）、设备类型（必填）、品牌、型号、序列号（填写则唯一）、状态、购置日期、购置价格、供应商、保修截止日期、责任部门、存放地点、备注 |
| 回写字段 | 当前领用人、领用开始时间、预计归还时间。由领用单维护，表单中只读 |
| 初始类型 | 笔记本、台式机、显示器、鼠标、键盘、转接头、投影仪。已被引用的类型只能停用，不能删除 |
| 删除 | 仅允许删除从未被领用单引用且状态为在库的设备。已有记录的设备走报废 |
| 详情 | 当前状态、当前领用、历史领用、状态变更记录 |
| 页面 | 设备列表、设备新建/编辑、设备详情 |

设备状态：在库、审批中、已领用、维修中、已报废。只有在库可被新申请。已逾期不改变设备状态，设备仍为已领用。

### 2.3 设备列表与过滤

| 项 | 说明 |
| --- | --- |
| 用户故事 | 作为管理员或职工，我按类型、状态和时间范围找到设备 |
| 筛选 | 设备类型（多选）、设备状态（多选）、领用时间范围、到期时间范围、关键字（名称/编号/序列号）、存放地点、责任部门。管理员另可筛领用人 |
| 组合 | 不同条件是并且；同一条件多选是或者。日期含首尾两天。开始日不得晚于结束日 |
| 时间条件 | 填写领用时间或到期时间后，只返回有对应日期的设备 |
| 普通用户 | 只能看到在库设备，以及本人申请中、领用中的设备。不提供领用人筛选，不展示购置价格 |
| 列表列 | 资产编号、名称、类型、状态、存放地点、领用人、领用时间、预计归还日。已逾期用醒目标识 |
| 其他 | 分页，默认按更新时间倒序。清空筛选恢复默认。导出使用同一套筛选条件 |

### 2.4 领用申请、审批与发放

| 项 | 说明 |
| --- | --- |
| 用户故事 | 作为职工，我申请一台在库设备；作为管理员，我审批并发放 |
| 申请字段 | 设备、用途（必填）、预计归还日（必填）、领用说明 |
| 日期规则 | 预计归还日晚于申请日，且不超过单次最长领用天数（默认 90 天） |
| 占用 | 提交后领用单为待审批，设备为审批中。草稿不占用设备。同一设备同时只有一条进行中的申请（草稿、待审批、已通过待发放、领用中） |
| 撤回 | 申请人可撤回待审批单据，设备回到在库 |
| 审批 | 管理员通过或驳回。驳回必须填写原因。状态变化后的重复操作被拒绝 |
| 发放 | 审批通过后设备仍为审批中，管理员发放确认后才变为已领用，并写入领用人、领用开始时间、预计归还时间 |
| 通知 | 提交后通知管理员；通过、驳回、撤回、发放后通知申请人 |
| 页面 | 申请页、我的申请、领用单详情、管理员待办 |

领用单状态：草稿、待审批、已通过、已驳回、已撤回、领用中、已归还、已逾期。已逾期是领用中且当前日期晚于预计归还日的展示状态。

### 2.5 归还

| 项 | 说明 |
| --- | --- |
| 用户故事 | 作为领用人，我申请归还；作为管理员，我验收后让设备重新在库 |
| 规则 | 领用中或已逾期可申请归还。确认前设备保持已领用。管理员可填写外观和附件情况。确认后单据变为已归还，设备回到在库，清空领用人与领用时间 |
| 代归还 | 管理员可直接归还确认，用于人员离职或设备已收回 |
| 通知 | 归还确认后通知申请人 |
| 版本 | MVP。续借不在此功能内 |

### 2.6 续借

| 项 | 说明 |
| --- | --- |
| 用户故事 | 作为领用人，我在到期前申请延长归还日 |
| 规则 | 新预计归还日必须晚于原日期。自发放日起的总时长不超过续借上限（默认 180 天）。同一单据有未完成续借时不能再发起。通过后更新到期日并按新日期提醒；若新日期晚于今天，清除逾期展示。驳回则保持原日期 |
| 版本 | V1.1 |

### 2.7 消息、站内信与邮件提醒

| 项 | 说明 |
| --- | --- |
| 用户故事 | 作为领用人，我在到期前收到站内信和邮件；作为管理员，我收到全机构汇总 |
| 时点 | 到期前 7 天、3 天、1 天，到期当天，逾期后每个自然日 |
| 管理员 | 只发站内信。按人汇总即将到期清单和已逾期清单，正文含资产编号、名称、领用人、预计归还日、逾期天数 |
| 领用用户 | 站内信 + 邮件，只含本人设备 |
| 可靠性 | 同一单据、同一时点、同一接收人每天至多一次。先写站内信再发邮件。邮件失败不撤销站内信，记入发送记录，管理员可重试。邮箱为空或邮件通道关闭时跳过邮件并记录原因 |
| 消息中心 | 未读/已读、全部已读、导航未读数。类型含待审批、审批结果、发放、归还确认、续借结果、到期提醒、逾期提醒、导入结果 |
| 版本 | 提醒与消息中心为 MVP。按消息类型筛选为 V1.2。邮件发送记录与重试为 MVP |

定时任务每天至少执行一次。漏跑后只补发当日应发提醒。

### 2.8 首页统计

| 视图 | 内容 |
| --- | --- |
| 管理员 | 指标卡：设备总数、在库、已领用、审批中、维修中、已报废、7 天内即将到期、已逾期、待审批。图表：状态占比、类型分布、近 6 个月领用次数。入口：待办、即将到期、已逾期 |
| 普通用户 | 指标卡：我的申请中、我的在用、我的即将到期、我的已逾期。图表：本人在用设备类型分布、近 6 个月本人领用次数。入口：我的申请、在库设备、未读消息 |

统计口径与列表一致。无数据时展示空状态。点击指标进入带筛选条件的列表。维修中、已报废指标在 MVP 可显示为 0，对应操作在 V1.1 开放。

### 2.9 导出

| 项 | 说明 |
| --- | --- |
| 用户故事 | 作为管理员，我把当前筛选结果导出为表格，用于报送或备份 |
| 规则 | 仅管理员。范围等于筛选结果，不受当前页限制。格式 xlsx，文件名含导出时间。默认导出列表可见列，管理员可勾选字段。上限默认 10000 行，超出时提示缩小范围。无数据时不生成空文件。记录审计日志。购置价格只出现在管理员导出中 |
| 版本 | MVP 导出固定列。可选字段为 V1.1，与审计日志一起交付 |

### 2.10 导入

| 项 | 说明 |
| --- | --- |
| 用户故事 | 作为管理员，我下载模板并批量入库，失败行可以改正后重导 |
| 必填 | 资产编号、资产名称、设备类型 |
| 校验 | 类型、部门、地点必须已存在且启用。编号和序列号在文件内、与系统内都不可重复。日期和价格格式不合法则该行失败 |
| 处理 | 合法行新增为在库。非法行跳过。整文件无法解析时不写入任何数据。空文件、表头不匹配、超过 2000 行时拒绝 |
| 结果 | 展示成功条数、失败条数、行号和原因，可下载失败明细 |
| 版本 | MVP，含模板下载 |

### 2.11 用户与角色

| 项 | 说明 |
| --- | --- |
| 用户故事 | 作为管理员，我创建职工账号并指定角色 |
| 字段 | 账号（唯一）、姓名、邮箱、手机、部门、角色、初始密码、启用状态 |
| 角色 | 仅系统管理员、普通用户。不提供自定义权限 |
| 保护 | 不能停用或删除自己。不能让启用中的管理员数量变为 0。停用后立即不能登录，其未完结领用单保留，管理员可代为归还 |
| 筛选 | 姓名、账号、角色、部门、启用状态 |
| 版本 | MVP |

### 2.12 部门与存放地点

| 项 | 说明 |
| --- | --- |
| 用户故事 | 作为管理员，我维护处室、课题组和房间，以便过滤设备 |
| MVP | 提供单层部门、单层地点的新增、改名、停用。设备表单用下拉选择 |
| V1.1 | 增加上级部门和上级地点。被引用项只能停用。停用后不能被新数据选用，历史名称仍显示 |

### 2.13 设备生命周期

| 操作 | 规则 | 版本 |
| --- | --- | --- |
| 入库 | 新增或导入，状态为在库 | MVP |
| 调拨 | 变更责任部门或存放地点，填写原因。已报废不可调拨 | V1.1 |
| 维修 | 仅在库可送修。记录送修日、故障、完成日、结果。完成后回到在库。已领用须先归还 | V1.1 |
| 报废 | 在库或维修中可报废并填写原因。报废后只读，保留历史领用 | V1.1 |
| 盘点 | 按地点或部门生成应盘清单，标记正常、缺失、位置不符，输出差异。不自动改领用和报废 | V1.1 |

以上写操作进入设备履历。

### 2.14 系统参数

| 参数 | 默认 | 版本 |
| --- | --- | --- |
| 提前提醒天数 | 7、3、1。至少保留到期当天 | V1.1 可改；MVP 使用默认值 |
| 单次最长领用天数 | 90 | 同上 |
| 续借后自发放日起最长天数 | 180 | V1.1 |
| 邮件通道 | 开启 | V1.1 可关；MVP 按部署配置启用或跳过 |
| 导入上限 | 2000 行 | MVP 固定 |
| 导出上限 | 10000 行 | MVP 固定 |
| 登录锁定 | 5 次 / 15 分钟 | MVP 固定，V1.1 可改 |

参数修改写审计日志，只影响之后的新申请和新提醒。

### 2.15 审计日志

记录操作者、时间、模块、动作、对象编号、变更摘要。覆盖设备变更、审批、发放、归还、导入导出、用户与角色、系统参数。只追加。管理员可按时间、操作者、模块、对象编号查询。V1.1 交付，并支持导出。

### 2.16 附件

V1.2。设备可上传图片和 pdf，限制大小与类型。普通用户可看设备照片，不能看价格类票据。删除记日志。

### 2.17 双视图差异

| 区域 | 管理员 | 普通用户 |
| --- | --- | --- |
| 首页 | 全机构指标、图表、待办、逾期 | 本人指标、本人图表、我的申请 |
| 设备 | 全部状态，可维护，可见价格 | 在库及本人相关设备，只读，无价格 |
| 领用 | 待审批、待发放、待归还；通过、驳回、发放、归还确认 | 我的申请和在用；提交、撤回、申请归还 |
| 数据与系统 | 导入导出、用户、部门、地点、参数、审计、邮件记录 | 不可见 |
| 消息 | 待办通知 + 到期/逾期汇总站内信 | 本人结果通知 + 到期/逾期站内信和邮件 |

## 3. 功能优先级

### 3.1 MVP（V1.0）

目标：跑通“入库 → 查询 → 申请 → 审批 → 发放 → 到期提醒 → 归还 → 再入库”，并完成统计、导入导出和两种视图。

| 模块 | MVP 包含 |
| --- | --- |
| 账号 | 登录、退出、改密、个人中心、失败锁定、启用/停用 |
| 设备 | 类型字典、台账增改查、受限删除、详情与履历中的领用记录 |
| 查询 | 类型、状态、领用时间范围、到期时间范围、关键字、部门、地点、领用人（管理员） |
| 领用 | 申请、草稿、撤回、通过、驳回、发放确认、我的申请、管理待办 |
| 归还 | 归还申请、归还确认、管理员代归还 |
| 提醒 | 默认时点的站内信和邮件、消息已读、邮件失败记录与重试 |
| 首页 | 分角色指标卡和三张图表，指标可下钻 |
| 导入导出 | 模板下载、行级校验、失败明细、按筛选结果导出固定列 |
| 权限 | 两种角色、菜单与接口双重校验、价格字段隔离 |
| 主数据 | 单层部门、单层地点 |

MVP 使用默认系统参数，不提供参数页面。维修、报废、盘点、调拨、续借、多级组织、审计查询、导出字段勾选不进入 MVP。首页上维修中和已报废显示为 0。

### 3.2 V1.1

| 模块 | 内容 |
| --- | --- |
| 续借 | 申请、审批、更新到期日、清除或保留逾期 |
| 生命周期 | 调拨、维修、报废、盘点差异清单 |
| 组织 | 部门与地点的上下级 |
| 系统参数 | 提醒天数、领用上限、续借上限、邮件开关、锁定策略 |
| 审计 | 查询与导出 |
| 导出 | 管理员自选导出字段 |

### 3.3 V1.2

| 模块 | 内容 |
| --- | --- |
| 附件 | 设备照片与票据，按角色控制票据可见性 |
| 消息 | 按类型筛选 |
| 体验 | 待办数和未读数在操作完成后立即更新 |

### 3.4 明确不做

多机构、多级审批、自定义角色、财务入账、采购流程、二维码打印、原生 App。

## 4. 界面设计要求

### 4.1 设计原则

- 面向内部办公，信息优先。列表、状态和待办比装饰更重要。
- 同一状态在全站使用同一颜色和同一文案。
- 主操作每页只有一个，例如“提交申请”“通过”“确认发放”。
- 危险操作使用二次确认，并写明后果。驳回、报废、停用管理员属于此类。
- 校验出现在字段旁边，说明怎样改。
- 空数据、无权限、邮件未配置都要有说明，不能只留空白。

### 4.2 视觉与状态

桌面端优先，内容区在 1280px 宽度下完整显示筛选区和表格主列。主色偏稳重蓝，用于主按钮和当前菜单。背景为浅灰，卡片为白色。

| 状态 | 呈现 |
| --- | --- |
| 在库 | 绿色标签 |
| 审批中 / 待审批 / 已通过待发放 | 蓝色标签 |
| 已领用 / 领用中 | 橙色标签 |
| 已逾期 | 红色标签，列表行同时加浅红色底 |
| 维修中 | 紫色标签 |
| 已报废 / 已驳回 | 灰色标签 |
| 已归还 / 已通过 | 中性绿色或完成态文字 |

即将到期（7 天内且未逾期）用橙色文字，不替换“已领用”状态。

字体使用系统中文界面字体。正文 14px，表格 13～14px，指标数字 24～28px。点击区域高度不小于 32px。

### 4.3 整体框架

登录后为左侧导航 + 顶栏 + 内容区。

- 顶栏左侧为产品名称“资产管理系统”，右侧为未读消息图标、当前用户姓名和角色、退出。
- 未读数大于 0 时在消息图标上显示数字，超过 99 显示 99+。
- 左侧菜单按第 2 节的角色菜单渲染，当前页高亮。
- 内容区顶部是页面标题和主按钮，其下是筛选区，再下是表格或图表。
- 面包屑用于详情和表单返回列表。

登录页独立，居中卡片，含系统名称、账号、密码、登录按钮、锁定提示。

### 4.4 关键页面

**管理员首页**

- 第一行 4～8 张指标卡，可换行。逾期和待审批放在前部。
- 第二行左侧状态占比环图，右侧类型分布条形图。
- 第三行领用趋势折线图，横轴为近 6 个月。
- 右侧或下方为待办列表，每行显示单号、申请人、设备、状态、提交时间，点击进入单据。
- 无数据时图表区显示“暂无数据”，指标为 0，仍可点击进入空列表。

**普通用户首页**

- 四张本人指标卡。
- 一张本人在用类型图，一张本人领用趋势图。
- 快捷入口：浏览在库设备、查看我的申请、打开未读消息。

**设备列表**

- 筛选区默认展开常用项：关键字、类型、状态。领用时间和到期时间使用日期范围选择器。更多筛选可收起。
- 查询、重置放在筛选区右侧。管理员在表格上方放“新建设备”“导入”“导出”。
- 表格操作列：管理员为详情、编辑；在库行额外显示“不可用原因”以外的状态操作放到详情中，避免列表过宽。普通用户在库行显示“申请领用”。
- 逾期行整行轻提示。分页放在表格下方，展示总条数。

**设备表单**

- 分组：基本信息、购置信息、位置与归属。购置价格仅管理员可见。
- 必填项标星。编号和序列号在失焦时检查重复。
- 底部固定“保存”“取消”。

**设备详情**

- 头部：名称、资产编号、状态标签、主操作。
- 管理员主操作按状态变化：在库可编辑、调拨、维修、报废；审批中进入对应单据；已领用可归还确认。
- 普通用户在库时主操作为“申请领用”；本人领用中时为“申请归还”。
- 中部为字段描述列表。下部为领用历史时间线。

**领用申请**

- 从设备详情进入时设备只读带出。
- 用途为多行文本，预计归还日为日期选择，超过最长天数的日期不可选。
- 底部“保存草稿”“提交申请”。提交前弹出确认，写明提交后设备将被占用。

**领用办理（管理员）**

- 页签：待审批、待发放、待归还、全部。
- 待审批行操作：通过、驳回。驳回打开对话框，意见必填。
- 待发放行操作：确认发放。
- 待归还行操作：确认归还，可填验收说明。

**我的领用（普通用户）**

- 页签：申请中、使用中、已完成。
- 使用中且已逾期的卡片或行显示剩余或逾期天数，以及“申请归还”。V1.1 增加“申请续借”。

**导入**

- 步骤：下载模板、上传文件、查看结果。
- 结果区分成功与失败。失败表展示行号、资产编号、原因，并提供下载。

**消息中心**

- 左侧或顶部：全部、未读。V1.2 增加类型筛选。
- 列表标题、时间、未读圆点。点击展开正文并标为已读。管理员的到期消息以表格列出设备。
- 提供“全部已读”。

**用户管理**

- 标准筛选 + 表格 + 抽屉表单。
- 停用使用确认框，说明该用户将不能登录、未归还设备仍保留。

### 4.5 反馈与异常界面

| 场景 | 界面 |
| --- | --- |
| 加载 | 表格和图表使用骨架或加载指示，不闪烁空白 |
| 保存成功 | 顶部轻提示，并返回列表或停留详情 |
| 业务拒绝 | 对话框或表单错误，例如“该设备当前为已领用，不能申请” |
| 无权限 | 独立提示页，提供返回首页 |
| 登录锁定 | 登录按钮下方显示剩余锁定时间 |
| 邮件未配置 | 邮件记录中显示未发送及原因；消息中心不报错 |
| 导入文件错误 | 停留在上传步骤，提示表头不匹配或超过行数上限 |

### 4.6 交互细节

- 列表筛选条件反映在地址查询参数中，刷新和从详情返回后仍在。
- 指标卡下钻带上对应筛选，用户能看出当前为什么是这个结果。
- 提交、审批、导入按钮在请求期间禁用，防止重复提交。
- 日期范围选择器禁止开始晚于结束。
- 表格列过多时固定资产编号和操作列，横向滚动。

### 4.7 响应与兼容

- 支持当前版本的 Chrome 和 Edge。
- 以 1440px 和 1280px 为主要验收宽度。
- 1024px 时筛选区折行，表格可横向滚动，仍能完成申请、审批和阅读消息。
- 不要求手机端独立布局。

## 5. 技术栈建议

建议采用前后端分离，便于机构内网部署和后续由 Java 方向的同事维护。

| 层次 | 选型 | 用途 |
| --- | --- | --- |
| 前端 | Vue 3 + TypeScript + Vite | 单页应用与工程化 |
| UI | Element Plus | 表格、表单、日期范围、对话框、分页 |
| 状态与路由 | Pinia、Vue Router | 登录态、角色菜单、页面权限 |
| 图表 | Apache ECharts | 状态占比、类型分布、领用趋势 |
| 请求 | Axios | 统一携带登录凭证、处理无权限和业务错误 |
| 后端 | Java 17 + Spring Boot 3 | 业务接口、校验、事务 |
| 安全 | Spring Security + JWT | 登录、角色校验、接口鉴权 |
| 持久化 | MyBatis-Plus + MySQL 8 | 台账、单据、消息、日志 |
| 缓存与锁 | Redis | 登录失败计数、提醒任务互斥 |
| 定时任务 | Spring Scheduling | 每日到期与逾期扫描 |
| 邮件 | Spring Mail | SMTP 发送，失败写入记录 |
| 表格文件 | EasyExcel | 导入模板、导入解析、导出 |
| 部署 | Nginx + Docker Compose | 静态资源、反向代理、应用与数据库同机编排 |

实现约定：

- 密码使用强哈希存储，接口走 HTTPS。
- 角色校验放在服务端。前端菜单隐藏只作为体验。
- 设备状态和领用单状态在同一事务中变更，避免出现“单已通过但设备未占用”。
- 资产编号、序列号使用数据库唯一约束，与导入校验同时生效。
- 提醒任务加分布式锁或数据库锁，多实例部署时一天只扫一次成功批次。
- 站内信提交成功后，邮件异步发送。失败可按记录重试。
- 导入先校验后写入合法行，失败原因按行返回。
- 审计日志与业务写操作同一事务，或在事务提交后可靠追加；日志不提供修改和删除接口。
- MVP 的部门与地点用单表，预留父级字段，V1.1 再打开层级界面。

目录建议在实现阶段分为 `frontend` 与 `backend`，文档继续放在 `docs`。数据库迁移脚本与后端放在一起。

## 6. 非功能性需求

### 6.1 性能与容量

按单机构、设备不超过 5 万、用户不超过 2000：

| 场景 | 要求 |
| --- | --- |
| 登录与打开首页 | 5 秒内看到指标和图表 |
| 带筛选的设备列表第一页 | 3 秒内返回 |
| 打开领用单详情 | 2 秒内返回 |
| 导入 2000 行 | 1 分钟内给出成功与失败明细 |
| 导出 10000 行 | 1 分钟内开始下载，或进入可查询的生成结果 |
| 每日提醒扫描 | 5 万设备规模下 10 分钟内完成当日发送 |

列表必须分页。统计可预先按日汇总，避免每次打开首页全表扫描。超出上述规模时导出改为异步，不在本版做分库。

### 6.2 安全

- 密码不明文存储，不明文写日志。
- 登录失败不区分“账号不存在”和“密码错误”。
- 连续失败锁定，阈值见系统参数。
- 停用用户的已签发登录态立即失效。
- 所有查询按角色过滤数据。普通用户接口不返回购置价格、供应商、他人领用说明。
- 导出接口再次校验管理员角色。
- 上传文件限制为图片和 pdf，单文件不超过 10MB，存储名随机化，响应头禁止当网页执行。
- 管理接口与普通接口使用同一套身份，不靠隐藏 URL。
- 关键写操作记录操作者、时间和对象编号。

### 6.3 可靠性

- 审批、发放、归还失败时整单回滚，设备状态与单据状态保持一致。
- 提醒先落站内信。邮件失败保留失败原因和重试次数。
- 同一提醒维度每天至多成功生成一次站内信。
- 定时任务失败要留下可查询记录，次日执行不重复补发历史日期。
- 数据库每日备份。导入前建议管理员自行导出当前台账。

### 6.4 兼容与易用

- Chrome、Edge 当前正式版。
- 桌面宽度 1280px 及以上完成全部管理操作。
- 表单错误、空列表、无权限、文件格式错误均有中文说明。
- 日期展示为 `YYYY-MM-DD`，时间展示为 `YYYY-MM-DD HH:mm`。

### 6.5 可维护性

- 设备类型、部门、地点、系统参数不写死在页面文案以外的业务代码分支里。初始类型由初始化数据提供。
- 状态枚举集中定义，前后端使用同一套编码。
- 提供初始化管理员账号的安装说明，密码在首次登录后修改。

| 编号 | 验收 |
